# オトナの音声入力 こえのたね（iPhone・iPad版）

iPhoneのキーボードは、マイクをタップして話し、「終了して貼り付け」をタップすると、確定した文が元の入力欄に入ります。確定を待つ間に入力先を移った場合は文章を保持し、自分で「貼り付ける」を押せます。貼り付けた文を直すときは、「空白」を長押ししたまま指を左右に動かすと、カーソルを移動できます。反時計回りの矢印（↺）を押すと、未確定の最後の文字が一つ前に戻ります（例：「う」→「い」）。iPadでは録音終了後に「修正する」「貼り付ける」を選びます。

iPhoneはキーボードの「配列」、または本体の「設定 → キーボード → キー配列」で「標準」「テンキー」を選べます。テンキーでは、左列の「あA1」でかな・英字・数字を順に切り替えます。かなの絵文字キーは「ま」の下にあります。↺ は左列の上から2番目、削除・空白・改行は右列です。

0.2.1（ビルド32）の初期設定では、マイクを使う理由を確認して「続ける」を押すと、初回は端末が使用の可否を尋ねます。「スキップ」で初期設定を閉じることもできます。

キーボードを閉じるには右上の「しまう」を押します。iPadの横向きで幅が十分あるときは、プレビューと文字キーを横に並べます。

ビルド31では、録音を止めた位置に「確定後に貼り付け」が出ます。押すと同じ入力欄に完成した文章が1回入ります。そのまま待つとプレビューで修正できます。待っている間に入力欄を変えた場合は、完成した文章を下書きとして保持します。破棄するときは「…」から「この文章を破棄」を選びます。

黄色の修正範囲は←で末尾を1文字短く、→で1文字長くできます。「先頭」か「全体」を選ぶと、矢印で動かす位置が切り替わります。

ビルド30では、iPhoneのプレビューと変換候補が同じ高さの枠を使います。「、」を続けて押す間もキーの位置が一定です。「修正する」で語の区切りが合わないときは「範囲を選ぶ」を押し、最初と最後の文字をタップしてください。「書き直す」では漢字の候補を選んだ後も文字や記号を足せます。「修正を確定」でプレビューに反映し、「貼り付ける」で本文に入ります。

音声入力では、認識区間の語尾と文の形を合わせて疑問符を調整します。平坦・下降調の言い切りに付いた疑問符は句点に戻し、「来られる」などは明瞭な上昇調のときに疑問符を補います。音高が取れない区間は認識結果を使います。任意の文章整形で疑問符が増えたり消えたりした場合にも、整形前の文を使います。

ビルド28では、話し終わったら「録音を終了」を押し、「修正する」か「貼り付ける」を選びます。「修正する」では本文に貼り付ける前に語を選んで直せます。プレビューは本文より少し大きい19pt（標準設定）で表示し、システムの文字サイズに合わせて拡大します。

日本語の音声入力と、その場で修正できる日本語テンキーを組み合わせたiPhoneアプリの開発コードです。公開中のMac版とは別のターゲットです。PC版と同じ「声と音波」の図柄を使用し、iOS配布用は透明度のない正方形で生成します。

## 構成

iOS用配布アイコンは `swift scripts/GenerateIcon.swift "$PWD" --ios-store-icon` をリポジトリ直下で実行して再生成できます。

TestFlight配布はBRANS BANK SYSTEMS, K.K.（Team ID: `NRX77TLPW7`）、本体Bundle IDは`jp.ainotane.koenotane.ios`、キーボードは末尾`.keyboard`、App Groupは`group.jp.ainotane.koenotane.ios`を使用します。App Store Connectの現行掲載名は「こえのたね — 日本語音声入力」です。開発版0.2.0の本体・キーボード表示名と次版の掲載予定名は「オトナの音声入力 こえのたね」です。旧Personal Teamの開発版とは別アプリになるため、辞書は書き出し・取り込みで移し、キーボード追加とフルアクセス設定を行ってください。

- iOS 26以降。実機確認の指定対象はiPhone 16 Pro Max / iOS 27.2.1。
- 本体アプリで日本語モデルとマイクを準備する。
- 他アプリの入力欄で、こえのたねキーボードのマイクをタップして開始・終了する。
- 音声認識はSpeechAnalyzer / DictationTranscriber（build 12以降、自動句読点を有効化）。クラウド認識への代替処理はない。
- Mac版と同一の辞書パーサー・フィラー除去・逐次認識の確定処理を使用。テストでファイルの一致を確認する。
- 任意の整形はApple IntelligenceのSystemLanguageModelのみ。初期状態はオフ。
- キーボード内で、かなフリック・連打による文字切替・漢字候補・濁点／半濁点／小文字・英字・数字・絵文字・削除・改行を操作できる。
- スペースの長押しと左右移動でカーソルを動かす。
- かな漢字変換はAzooKeyKanaKanjiConverter v0.11.2の辞書変換。ニューラル変換のTraitsは有効にせず、学習保存も無効にする。
- セットアップは、モデル準備 → キーボード追加 → マイク許可 → 使い方 → 短文・メール・メモの入力練習の順。
- 直近5件の履歴、辞書の手動追加・ファイル取り込み、指定文での精度／処理時間の計測。

キーボードからの本体起動はSwiftUIのLinkと、こえのたね専用のURLスキームを使用します。開始操作には共有領域で発行した有効期限60秒・一度限りのチケットが必要です。URLに入力本文や音声は含めません。マイクが使えないときのタップは本体へ引き継ぎ、専用画面から直前のアプリへ右にスワイプで戻ると、開始操作をしたキーボードで聞き取りを開始する設計です。別アプリのURLや非公開セレクター、ホストアプリの探索は使用しません。自動で別アプリを開き直す実装ではなく、本体が開くことは実機確認済みです。キーボードから開いた場合は、通常ホーム画面の代わりに「スワイプしてアプリに戻る」の専用案内を表示します。

同じテンキーを0.8秒以内に続けてタップすると末尾の未確定文字を切り替えます。「、」の4回タップは「！」です。時間を空ける・別キーを押す・カーソルを動かす・確定する操作で連打を区切ります。フリックは従来どおり別の文字を追加します。

削除キーはタップで1文字、長押しで連続削除、左フリックでカーソル直前の最大10文字をまとめて削除します。行内の残りが10文字未満なら、その分だけ削除します。改行を越えて段落をまとめて削除しません。

## データとマイク

音声をファイルに保存しません。待機中もマイクを維持するためiPhoneの使用表示が出ますが、音声入力を開始していない間の音声は認識器へ渡さず、保存もしません。待機は1・5・10分から選べ、初期値5分。最後の音声入力から数え、聞き取り中・文章の確定中は延長します。本体から終了できます。通話・音声経路変更・期限切れでは終了します。

アプリとキーボードはApp Groupの専用領域で連携します。フルアクセスはこの連携に必要です。音声・辞書・履歴・手入力した文字列をネットワークへ送る実装はありません。日本語モデルの取得はAppleのAssetInventoryが行います。外部サポートリンクや結果の共有は利用者の操作で開きます。

共有ファイルは0600・原子的な更新・排他ロックを使用し、バックアップ対象から除外します。履歴は5件、計測結果は50件まで。履歴保存のオフは既存データを削除しません。削除は画面のボタンで行います。手入力のかな漢字変換はメモリ内で処理し、学習履歴を保存しません。

入力先・キーボードの表示回・リクエストを照合し、異なる欄や古い要求へ結果を挿入しません。挿入を先に一度だけ予約してからUIKitへ渡します。予約直後のクラッシュなどで入力されなかった場合は、履歴からコピーできます。自動的な再挿入はしません。

## ビルド

Xcode 26以降とiOS SDKが必要です。Command Line ToolsだけではiPhoneアプリをビルドできません。

1. iOS/VoiceSeed.xcodeprojをXcodeで開く。
2. VoiceSeed-iOSスキームを選ぶ。
3. 実機で動かす場合は、自分の開発チーム・アプリ識別子・App Groupに対応するプロビジョニングを設定する。識別子はConfig/Project.xcconfigで変更でき、App Groupは本体とキーボードで同じ値を使用する。
4. iPhoneを選んでRunする。

証明書・プロビジョニングファイル・個人アカウント情報はリポジトリに含めません。署名なしのSimulatorビルドを、iPhoneにそのまま入る配布物とは扱いません。

開発チームをこのMacだけで保持する場合は、リポジトリ直下の`.ios-signing.local.xcconfig`へ`DEVELOPMENT_TEAM = 自分のチームID`を設定できます。本体とキーボードの両方へ適用し、このファイルとXcodeのワークスペース情報はGitと公開ソースアーカイブから除外します。

~~~sh
python3 iOS/Scripts/generate-project.py --check
bash iOS/Scripts/test-core.sh
swift test --package-path iOS
xcodebuild -project iOS/VoiceSeed.xcodeproj -scheme VoiceSeed-iOS \
  -configuration Debug -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath iOS/.build/DerivedData CODE_SIGNING_ALLOWED=NO build
~~~

test-core.shはiOS SDKやXCTestを持たないAppleシリコンMacでも、合成データだけで共有プロトコル・保存・フィラー除去などを検証します。swift testはXCTestを含むXcode環境で実行します。App Groups・マイク・キーボードからの本体起動・背景動作・実際の他アプリへの入力は、実機で確認する別の項目です。

### 実機の音声入力テスト

本体から入力先へ戻る際、iOSはキーボード画面と入力欄の識別情報を作り直す場合があります。開始要求の所有者は拡張プロセス内で保持し、復帰後に見えている入力欄と表示回へ結果を紐付けます。古い要求や別プロセスからの引き継ぎは拒否します。共有状態が一時的に使用中の場合は、開始・終了を短い間隔で再試行します。

XcodeのDevice HubでiPhoneの「View Screen」を開いたまま音声をテストしないでください。画面操作中はiPhoneのマイクを使えず、アプリへ無音が渡る場合があります。[Appleの説明](https://developer.apple.com/documentation/xcode/interacting-with-your-app-in-device-hub)。Device Hubの画面接続を終了し、iPhone本体でマイクを一度終了して有効にし直し、iPhoneに向かって話します。Xcodeのデバッグ接続だけは維持できます。

Debugビルドに限り、`--synthetic-dictation`を起動引数に指定すると「明日の打ち合わせは午後3時からです。」という固定文で共有領域からキーボードへの挿入経路をテストできます。実機では通常のマイク待機を維持しますが、音声を認識器へ渡しません。通常の認識テストではこの引数を外します。Releaseビルドはこの引数を無視します。固定文が入っても音声認識の成功とは扱いません。

シミュレータのDebugビルドで確定待ちを再現するには、起動引数に `--keyboard-edit-benchmark --synthetic-dictation --slow-finalization` を指定します。テスト用の入力欄で録音を終了すると、固定文の確定まで4秒待ちます。iPhoneは終了時に、iPadは「確定後に貼り付け」を押したときに、同じ欄に一度だけ入ることと、別の欄に移ったときは下書きに残ることを確認できます。

Debugの診断ログには処理段階、音声フレーム数、音量の集計値、結果の文字数だけを出します。音声や認識した本文は出しません。`test-core.sh`では、合成波形を使い、マイクバッファの再利用後にも音声が保持されることと48kHz→16kHz変換を検証します。

プロジェクトはScripts/generate-project.pyで決定的に生成します。新しいソースを追加した場合は再生成します。

## 精度と時間の測り方

「精度・速度」で、Macと比較できる同じ指定文を読みます。認識結果と整形後の文字誤り率（空白を除いたUnicode文字単位の編集距離）、終了操作から認識確定までの時間、任意の整形時間を別々に表示します。計測結果は明示操作で共有できます。

キーボード入力の履歴には、終了操作からUIKitへの挿入操作までの時間も記録します。実際に入力欄へ文字が入ったことは実機で確認します。数値だけから、認識精度や操作感がMac版や他製品と同等であるとは扱いません。
